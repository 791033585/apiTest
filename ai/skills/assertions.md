# 接口断言 Skill

## 断言顺序

断言按以下顺序组织：

1. `status_code`：校验文档声明的 HTTP 状态码。
2. `json`：校验响应 JSON 字段存在、字段值、字段类型或结构。
3. `header`：只校验文档声明或协议必需的响应头。
4. `response_time`：只有测试要求明确给出性能阈值时才生成。

## 断言规则

- 一个用例可以包含多个断言，但所有断言必须服务于同一个测试场景。
- JSONPath 必须以 `$` 开头，并指向响应中真实存在或文档声明存在的字段。
- 字段类型断言使用框架支持的表达方式，不输出 Python 表达式或脚本。
- 不要只断言状态码；成功响应至少补充一个文档能够支持的结构或字段断言。
- 不要臆造固定业务值、数据库值、错误消息或数组长度。
- 断言操作符只能使用 `eq`、`ne`、`contains`、`gt`、`ge`、`lt`、`le`。
