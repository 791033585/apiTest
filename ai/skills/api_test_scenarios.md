# 接口测试场景 Skill

## 每个接口的场景优先级

在文档信息足够时，按以下顺序设计，每个接口最多生成 20 条用例，不要为了凑数量生成无依据的场景。实际数量由接口约束和测试需求决定：

1. 正常场景：使用 `example`、`default` 或符合 schema 的最小有效数据。
2. 必填校验：缺少一个 required 参数或字段。
3. 类型校验：传入与 schema.type 不匹配的数据。
4. 空值校验：对允许推导的字符串、数组或对象使用空值。
5. 边界场景：使用 minimum、maximum、minLength、maxLength、minItems、maxItems 的边界值。
6. 枚举场景：使用 enum 外的值，仅在文档明确存在 enum 时生成。

## 约束

- 没有 schema 约束时，不要为了凑数量制造异常数据。
- 一个用例只验证一个主要测试意图，标题要能说明场景。
- 负向用例的预期状态码必须来自文档；文档没有声明时，只保留可推导的结构断言，并在 `notes` 说明。
- 账号、密码、Token、ID 等示例值只能使用文档 example/default 或项目明确提供的演示数据。
- 生成依赖场景前，必须确认前置接口能提取后置接口需要的变量。
